02

실제 GT ROI와 저장된 예측

실제 PACO Val 4개 이미지에서 고른 6개 ROI입니다. 박스·라벨·점수는 기존 manifest / prediction cache에서 읽었습니다. 이해를 위한 선택 예시이며, 대표 정확도를 추정하는 표본은 아닙니다.

명시적 positive · y=1명시적 negative · y=0unknown · y=-1 · 단순 ranking에서 제외
속성GT labelC0 logitC0 sigmoidP768 logitP768 sigmoid평가 시 의미

예측 출처: C0의 R2 ep6와 P768 Cosine의 R2 ep5, 모두 official Val manifest의 동일 ann_id. 두 모델의 head는 별도로 학습했고 epoch 선택 규칙도 다릅니다. 점수의 절댓값을 서로 같은 확률 보정으로 해석하지 않습니다. 위 B는 384 입력을 설명하는 위치 시각화이며, 표의 P768은 실제 full_size=768 결과입니다. 실제 token 값·attention은 이 그림에 표시하지 않았습니다.

“ROI feature”에도 여러 경로가 있습니다

Native / coarse-only: full-image grid의 ROI와 겹치는 token을 직접 읽는 조건도 있습니다. Bilinear / fused: ROI를 C0와 같은 24×24 query grid로 샘플링합니다. P는 coarse와 fine을 각각 샘플링한 뒤 Q = A + s_d W_d(F)로 융합합니다.

Bilinear 구현은 grid_sample, align_corners=False, padding_mode=border입니다. P384의 원래 map은 coarse 24×24×768 / fine 48×48×384이고, P768은 coarse 48×48×768 / fine 96×96×384입니다. 여기서 확인한 fused readout은 두 해상도 모두 ROI당 24×24×768로 읽습니다. 576개 출력 token이 생겨도 그만큼의 새 영상 정보가 생긴다는 뜻은 아닙니다.

C0가 “Oracle”인 이유와 한계

GT box를 알고, 원본 crop을 크게 확대하여 encode할 수 있는 참조 조건입니다. Student보다 작은 object의 세부 픽셀을 많이 볼 수 있습니다.

속성 label을 입력으로 주거나 속성을 완벽히 아는 oracle이 아닙니다. 학습한 probe를 거쳐야 하고 AP도 100이 아닙니다. Crop에서 문맥을 잃을 수 있어 모든 Part에서 이론적 상한이라고 할 수도 없습니다.

이 프로젝트의 PACO 속성 점수는 학습한 분류 head의 출력입니다.

두 대표 reader는 입력 feature가 같아도 읽는 방식과 학습 용량이 다릅니다. 각 feature 조건에 대해 reader/head를 별도로 학습하는 비교가 기본입니다.

R2는 단순 linear probe가 아닙니다. 위치·coverage·box 크기 정보를 활용하고 cov > 0인 token을 읽습니다. 내부 attention의 QK 유사도는 읽기 연산이고, 최종 PACO 점수는 59개 분류 logit입니다.

Cosine alignment와 AP를 구분하세요. Teacher crop과 Student feature의 cosine은 표현 학습의 loss·진단값입니다. PACO 평가에서는 teacher와의 cosine을 점수로 쓰거나, “wood” 텍스트 embedding과 비교하지 않습니다. Probe가 만든 logit → sigmoid → attribute ranking → AP의 순서입니다.
p_a = sigmoid(ℓ_a) = 1 / (1 + exp(-ℓ_a))
59개 속성은 sigmoid로 각각 예측합니다. 1,000-way ImageNet 분류처럼 softmax 합을 1로 만드는 방식이 아닙니다. 한 ROI가 black·striped·fabric·opaque를 동시에 가질 수 있습니다.
04

무엇을 학습하고, 추론에 무엇이 남는가

STAGE A / REPRESENTATION

Encoder 표현 학습

원본 DINOv3 baseline과 C0는 encoder 추가 학습이 없습니다. G1·P 계열 Student는 crop teacher 정렬 등의 loss로 encoder를 학습한 checkpoint입니다.

Teacher는 보통 고정된 원본 DINOv3입니다. G1-cross·MAE·PixelDiT처럼 decoder를 쓰는 조건은 구조·목적이 다르므로 각 조건의 추론 경로를 따로 확인합니다.

STAGE B / ATTRIBUTE PROBE

PACO 속성 판별 학습

표현 checkpoint를 고정한 채 R0의 head 또는 R2의 reader+head를 PACO train으로 학습합니다. 기존 공통 recipe는 10 epoch, masked BCE, seed 0입니다.

Attribute label이 알려진 항목만 loss에 포함합니다. Encoder에 속성 label로 gradient를 보내는 end-to-end fine-tuning과 구분해야 합니다.

STAGE C / INFERENCE

모든 가중치를 고정

GT box로 ROI를 지정하고 reader/head가 59개 점수를 출력합니다. GT attribute label은 추론 입력으로 사용하지 않습니다. label은 나중에 loss/AP 평가 시에만 씁니다.

공식 Test는 미리 선택한 reader epoch으로 평가합니다. 어떤 epoch을 고르는지는 실험마다 다르며, 아래 예시도 선택 규칙을 명시했습니다.

05

점수의 순서를 바꾸면 AP가 달라집니다

설명용 가상 예시 같은 category의 같은 attribute만 평가한다고 가정합니다. 예: chair / wood. Positive 3개, negative 2개, unknown 1개의 점수를 바꿔 보세요. 실제 실험 결과가 아닌 단일 ranking unit의 계산 예시입니다.

101-point interpolated AP
Known positive / negative3 / 2
Unknown 제외1 ROI

각 ROI의 attribute score

“순서 유지·점수 축소”는 초기 예시의 순서를 유지합니다. AP는 유지되지만 0.5 이상으로 판정되는 개수는 달라집니다. Unknown의 점수를 바꿔도 이 단순 예시의 AP는 변하지 않습니다.

Precision–Recall 곡선

파란 점과 점선은 raw PR, 초록 선·영역은 precision envelope입니다. Recall 0.00~1.00의 101개 지점에서 envelope precision을 읽어 평균합니다. 동점은 같은 threshold로 묶어 처리합니다.

순위ROIGTScore누적 TP / FPPrecisionRecall표시 threshold

왜 한 ROI의 “정답률”이 아닌가?

한 ROI는 59개 점수를 냅니다. AP는 이 ROI 하나만 보고 정하지 않고, 해당 category·attribute의 여러 ROI 점수를 모아 계산합니다. 높은 점수의 false positive가 앞에 오면 precision이 낮아집니다.

Pair에서 score_positive > score_negative인지 보는 진단은 AP 실패를 이해하는 도구입니다. Pair 정확도 자체가 AP는 아닙니다.

이 시뮬레이터의 범위

알려진 GT ROI의 순위를 설명하는 계산입니다. 공식 evaluator의 bbox 매칭, IoU threshold 10개, 중복 detection, unknown ignore, image당 detection 제한을 재현하는 전체 evaluator는 아닙니다.

공식 코드는 stable sort로 detection별 PR을 계산합니다. 동점 묶음을 사용하는 이 예시·project M2와 동점 처리도 다를 수 있습니다.

공식 evaluator에 실제로 무엇을 넘기나요?

각 official GT annotation에 대해 detection 하나를 만듭니다. 속성 정답으로 detection을 고르거나 score를 보정하지 않습니다.

{
  "image_id": image_id,
  "category_id": GT_category_id,
  "bbox": original_GT_bbox_xywh,
  "score": 1.0,
  "attribute_probs": [sigmoid(logit_0), ..., sigmoid(logit_58)],
  "gt_ann_id": annotation_id
}

gt_ann_id는 정렬 검증용입니다. Evaluator는 이 ID로 정답 연결을 강제하지 않고 실제 bbox IoU 매칭을 수행합니다. Model 입력 crop은 outward-rounded integer box를 쓰고, evaluator에는 원래 float GT bbox를 전달합니다.

공식 attribute ranking score = detection score × attribute probability
= 1.0 × sigmoid(logit_a)

GT box를 넣으므로 localization 성능은 사실상 고정되지만, 겹친 동일 category의 ROI 매칭·unknown ignore·max_dets 등 공식 규칙은 남습니다. Official code를 바꾸어 생략하지 않았습니다.

미주석 ROI와 detection 제한은 어떻게 처리하나요?

학습과 project ranking은 label -1을 제외합니다. 공식 평가는 먼저 object/category bbox 매칭을 수행한 뒤, attribute type이 unknown인 GT와 연결된 unmatched attribute prediction 등에 공식 ignore 규칙을 적용합니다. 단순히 모든 미주석 ROI를 negative로 계산하지 않습니다.

PACOResults(max_dets=300)은 이미지당 detection을 300개로 제한합니다. Val에서는 누락이 0개이며, 공식 Test에서는 11개 이미지에서 총 1,372개 detection이 이 제한으로 제외된 기록이 있습니다. Score가 모두 1.0이므로 입력 annotation 순서가 같은 점수 간 유지됩니다. 이 때문에 “GT box를 전부 제공했으니 모든 GT가 최종 평가에 남는다”는 가정도 확인해야 합니다.

hierarchical.obj-attr-AP가 Object, hierarchical.obj-attr-part-AP가 Part입니다. joint_attr_summary.AP는 joint pair를 평평하게 집계한 다른 요약이므로 동일 값이 아닙니다. Bbox AP가 100에 가까운 것은 GT box/category를 입력했기 때문이며 속성 예측이 완벽하다는 뜻이 아닙니다.

모델SplitObject APPart APOverall*Reader 선택 규칙

* Overall은 공식 두 level 점수의 반올림 전 값을 평균한 프로젝트 요약입니다. C0 ep6는 Nov6 실험의 held-out PACO train dev-M0 선택을 재사용했고, P768 ep5는 official Val의 mean(Object,Part)가 가장 큰 epoch입니다. 이 표는 평가 결과를 읽는 예시이며, 동일 선택 예산의 통제 실험으로 해석하지 않습니다. CI를 다른 분석에서 가져와 붙이지 않았습니다.

09

헷갈리기 쉬운 질문

결국 “feature → linear probe”가 맞나요?
Mean Probe(R0)에서는 맞습니다. Coverage mean → z-score → linear head입니다. 주요 R2 결과는 학습한 attention reader → linear head이므로 더 큰 판별 모델을 거친 점수입니다. 두 결과를 같은 이름의 linear probe라고 부르면 안 됩니다.
Crop과 Student가 같은 probe를 쓰나요?
구조·학습 recipe는 맞추지만 보통 각 feature에 별도 reader/head를 학습합니다. Crop용 head를 Student에 그대로 쓰는 실험은 별도 transfer 진단입니다. 이 가이드의 실제 예측도 independent probe 결과입니다.
Cosine이 높아졌는데 AP가 안 오르는 이유는요?
Teacher와 개별 ROI feature가 비슷해지는 것과, 같은 category에서 attribute positive를 negative보다 높은 점수로 정렬하는 것은 다른 조건입니다. 평균 방향·배경 정보의 정렬이 좋아져도 속성의 미세한 차이와 head의 판별 방향은 개선되지 않을 수 있습니다. 이는 가능한 설명이며, cosine 값만으로 원인을 확정할 수는 없습니다.
0.5보다 높은 속성을 맞힌 개수가 점수인가요?
아닙니다. 0.5는 표시용 threshold로 쓸 수 있지만 AP는 threshold를 바꿔가며 얻는 PR 관계를 요약합니다. 같은 unit 내 점수의 순서가 핵심이며, sigmoid는 단조 증가하므로 수치 반올림·포화가 없다면 logit과 sigmoid의 ranking이 같습니다.
GT ROI 점수를 실제 검출 성능이라고 부를 수 있나요?
Box·category가 정답인 조건의 attribute 성능입니다. 검출기의 위치 오류, category 오류, 누락·중복 생성까지 포함한 end-to-end PACO detection 성능과 구분해야 합니다. 또한 여기서 사용한 공식 평가의 IoU 타입은 bbox이며 segmentation AP가 아닙니다.
ImageNet 83.94%와 PACO AP는 무엇이 다른가요?
앞서 확인한 ImageNet 실험은 전체 이미지 CLS(768차원) → 별도 Linear(768→1000)의 Top-1 정확도입니다. PACO는 ROI 공간 token → 속성 reader/head(59 sigmoid) → category·attribute별 AP입니다. 입력 feature·label·평가 지표가 모두 다릅니다.

검증 범위와 표본 선택

C0·P768 prediction의 ann_id / image_id / category_id가 official Val manifest 전체 31,919행과 같은지 검사했습니다. 선택한 6 ROI의 label은 원본 annotation에서 다시 구성하여 cache와 일치함을 확인했습니다. 저장 logit에 sigmoid를 적용한 값도 기존 probs와 일치합니다.

4개 이미지와 6개 ROI는 객체·부분·재질·무늬 설명을 위해 고른 사례입니다. 유의성·일반화 성능을 검정하는 샘플이 아니며, 예시를 고르기 위해 model을 다시 실행하지 않았습니다. 그리드는 입력 기하 시각화이고 feature PCA·attention heatmap이 아닙니다.
